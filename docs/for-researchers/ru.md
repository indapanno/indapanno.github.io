# Навигатор по истории палийских терминов — для исследователей и разработчиков

Технический документ. Описывает архитектуру, схему данных и способ развёртывания
статического сайта. Для инструкции по добавлению термина через веб-интерфейс см.
[how-to-add-term_ru.html](https://indapanno.github.io/how/how-to-add-term_ru.html).

## Технический стек

- Frontend: чистый HTML/CSS/vanilla JS, без фреймворков и сборщиков (webpack/vite не используются).
- Сборка: Node.js-скрипт, выполняется в GitHub Actions (не требует Node локально, если не редактируешь код сборки).
- Хостинг: GitHub Pages, `Deploy from a branch`, ветка `main`, папка `/ (root)`. Сайт живёт в корне домена: `https://indapanno.github.io/` (репозиторий `indapanno.github.io`).
- Данные: JSON-файлы в git, без базы данных и бэкенда.
- Валидация: JSON Schema (draft-07) + клиентский валидатор без зависимостей.
- Аналитика: GoatCounter (внешний счётчик, без cookies).
- Личные данные читателя: отметки «Изучен / Не изучен» хранятся только в `localStorage` браузера и на сервер не отправляются (см. раздел «Отметки «Изучен» и страница «Мой прогресс»»).

## Архитектура сборки

1. Push с изменениями в `json/**`, `_src/templates/**`, `js/render-term.js`, `js/thai-numerals.js`, `.github/scripts/build-terms.js` или `.github/scripts/site-config.js` триггерит `build-terms.yml`; ветка — `main`. Сборку можно запустить вручную: Actions → Build terms → Run workflow (бот закоммитит результат). Локально сгенерированные страницы коммитить не нужно.
2. `build-terms.js` читает все `<id>_ru.json` / `<id>_thai.json`, объединяет id по обоим языкам.
3. Для каждого id генерирует карточку на каждом языке (`terms/<id>_ru.html`, `terms/<id>_thai.html`) — если перевода нет, рендерит блок «перевод отсутствует» со ссылкой на `/how/how-to-translate-term_*.html` и `<meta name="robots" content="noindex">`. У карточек с переводом — `canonical`, `hreflang` (ru/th/x-default, если переведены оба языка), `meta description` (из `interpretation`, иначе `reason_introduced`), Open Graph.
4. Пересобирает `index_ru.json` / `index_thai.json` (манифест для клиентского поиска: `id`, `term_ru`/`term_thai`, `later_count`).
5. Пересобирает страницы навигатора с пагинацией (10 терминов/стр, реальные статичные файлы: `index.html` в корне — первая страница русского списка (адрес `/`), остальные страницы — в папке `nav/`: `nav/nav_ru_2.html` и т.д., у тайского `nav/nav_thai.html`, `nav/nav_thai_2.html`, поэтому корень не растёт; не `?page=N` — важно для индексации и работы без JS); `canonical`/`prev`/`next` (у страницы 2 русского списка `prev` ведёт на `/`), а на первой странице каждого языка — `hreflang` и `meta description`/Open Graph. Язык без единого термина получает `noindex` вместо этих тегов. Каждая плитка — `<li class="term-item">` со ссылкой на термин и кнопкой `<button class="learned-btn" data-learned-id="<id>">` (в HTML лежит текст-заглушка «Не изучен» / «ยังไม่ได้เรียน», актуальное состояние проставляет `learned.js`).
6. Пишет заглушки на прежних адресах: `terms/index.html`, `nav/index.html` и `how/index.html` → `/`; шесть заглушек `how-to-*.html` в корне → `/how/…`; в корне `nav_ru.html` … `nav_thai_5.html` (по 5 на язык, не больше `LEGACY_NAV_MAX`) ведут на новые адреса в `nav/` и на `/` (общий шаблон заглушки лежит в `site-config.js`). Удаляет осиротевшие карточки (в `terms/` — id, которого больше нет в `json/`) и лишние страницы пагинации (в `nav/` — выше числа страниц; в корне — заглушки выше числа страниц и выше 5). Остальные файлы (`how-to-*`, `progress_*`, `404.html`, `index.html` и другие ручные) уборка не трогает. Идентификаторы терминов `index` и зарезервированные имена (`nav_…`, `progress_…`, `terms`, `bundle`, `css`, `js` и т. п., см. `RESERVED_ROOT` в `site-config.js`) дают ошибку сборки.
7. Генерирует `sitemap.xml` — только реально переведённые карточки (заглушки «перевод отсутствует» исключены) и страницы навигатора (первая страница русского списка — адресом `https://indapanno.github.io/`), с `hreflang` между языковыми версиями термина. Заглушки в карту не входят. Без `lastmod` (git-даты в GitHub Actions недостоверны).
8. Коммитит результат с флагом `[skip ci]` (иначе бесконечный цикл триггеров).

`render-term.js` — общий модуль между Node (используется через `require()` в
`build-terms.js`) и браузером (сейчас на сгенерированных страницах не задействован,
контент уже запечён в HTML на этапе сборки; модуль оставлен на случай будущего
клиентского рендера, напр. live-превью в валидаторе).

## Язык страницы

- **Единый источник.** Язык страницы определяется атрибутом `<html lang>`, который ставит сборка (`ru` / `th`). `lang.js` отдаёт его как `TermsLang.get()` → `'ru'` или `'thai'`; остальные скрипты (`learned`, `search`, `burger-menu`, `term-count`, `footer-counter`, `progress`, `validator-page`) берут язык оттуда, а не из имени файла. Поэтому имена вида `nav_thai_2.html` язык не ломают.
- **Переключатель языка** (`lang.js`): с карточки термина ведёт на `<id>_<другой язык>.html`; с любой страницы навигатора (`/`, `/nav/nav_<язык>[_N].html`) — на первую страницу другого языка (`/` или `/nav/nav_thai.html`): страницы 2+ у языков не соответствуют друг другу; со страниц связок (`/bundle/…`) — на ту же связку или на список другого языка; со страниц публикаций (`/publications/`, `publications_<язык>[_N].html` и самих статей) — на первую страницу списка публикаций другого языка: статьи не переводятся. Таблица адресов зашита в `buildTargetUrl` (`js/lang.js`).
- **Новый язык.** Добавить его код в `LANG_BY_HTML_LANG` в `lang.js` (плюс шаги из раздела «Отметки «Изучен»…»).
- **Разметка шапки.** Блок `header-controls` с группами `#lang-switch` (ссылки RU / ไทย) и `#theme-switch` (три кнопки) лежит в `_template_*.html`, `_layout_*.html` и в ручных страницах (`how/how-to-*`, `progress_*`). Стили `.segmented` — в `style.css`; `href` и активное состояние расставляют скрипты.
- **Запоминание языка.** При клике по языку `lang.js` пишет ключ `terms-lang` (`ru` / `thai`); читает его только `404.html`. Порядок определения языка там: адрес → страница-источник своего сайта → `terms-lang` → оба языка.
- **Правка шапки.** Меняется блок во всех шаблонах (включая `_src/bundle/template/_layout_*.html` и `_src/publications/template/_layout_*.html`), затем нужен ручной запуск «Build terms» (Actions → Build terms → Run workflow) и правка ручных страниц. Каркасы связок и публикаций пересобираются своими workflow при push в `_src/bundle/**` и `_src/publications/**`.

## Вёрстка на узких экранах

- **Правило (≤479 px).** Колонка `1fr` растягивается длинным словом (например, «сформировавшимся») и ломает карточку. В новых сетках в `style.css` использовать `minmax(0, 1fr)`.
- **Уже применено.** `.meta-grid` на `minmax(0, 1fr)`, блок «Атрибуция» идёт одной колонкой, у `.field-text` и ссылок в `main` задан страховочный `overflow-wrap`. На широких экранах вид не меняется.
- **Чего не делать.** `hyphens: auto` не использовать: перенос с дефисом в начале строки.

## Схема термина (JSON)

Один файл на язык. Единственное различие в ключах между языками: `term_ru` ↔ `term_thai`.

| Ключ | Тип | Описание |
|---|---|---|
| `id` | string | латиницей, строчными, без диакритики — совпадает с именем файла |
| `term_ru` / `term_thai` | string | термин на языке карточки; капитализируется автоматически при сборке (только RU — в тайском нет заглавных букв) |
| `term_iast` | string | транслитерация IAST, не капитализируется |
| `term_composition` | object | `{is_compound, components: [{part_iast, part_meaning}], note}` — см. ниже |
| `origin` | object | `{type, source_tradition, attestation_before_term, etymology_versions[]}` |
| `dating` | array | `[{type, value, comment}]` |
| `attribution` | object | `{traditional, academic, consensus}` |
| `recorded_by` | string | кем зафиксирован письменно |
| `school_tradition` | string | школа/пласт традиции |
| `reason_introduced` | string | зачем термин понадобился — простым языком |
| `interpretation` | string | толкование — простым языком |
| `language` | string | обычно `"пали"`, с уточнением для сложных случаев |
| `sources` | array | `[{status, title, location, transmission_tradition, language, source_type, discrepancies}]` |
| `later_mentions` | array | `[{id, parent, author_id, date_updated, updated_by, reason_for_update, what_is_new, school_tradition, source_type, language, source: {title}}]` — набор ключей одинаков для обоих языков, различаются только значения |

**`term_composition`** — для терминов, состоящих из двух и более САМОСТОЯТЕЛЬНЫХ
пали-слов (напр. `paṭicca`+`samuppāda`, `sati`+`upaṭṭhāna`). Разбор на приставку и
корень одного слова (напр. `du-`+`kha` в `dukkha`) сюда не относится — это
народная этимология, для неё `origin.etymology_versions`. `render-term.js` рендерит
блок «Из каких слов состоит» только при `is_compound: true`.

Полный эталонный пример — любой существующий файл, напр. `json/dukkha_ru.json`.

### Формальная JSON Schema

`schema/term.schema.ru.json` и `schema/term.schema.thai.json` (draft-07) формализуют
таблицу выше и проверены на всех терминах репозитория. Поля с закрытым набором
значений — `origin.type`, `origin.etymology_versions[].type`, `dating[].type`,
`sources[].status` — проверяются шаблоном «корень + необязательное уточнение в
скобках», а не жёстким списком: сами эти root-значения фиксированы (совпадают с
вариантами в `term-prompt-*.js`), но автору не запрещено уточнить их в скобках.
`sources[].source_type` и `later_mentions[].source_type` намеренно оставлены
свободным текстом — это открытый, растущий словарь формулировок, а не список из
нескольких вариантов. Обе схемы использует онлайн-валидатор (см. ниже); их же можно
подключить для автодополнения в редакторе.

## Онлайн-валидатор JSON

Страница `how-to-check-json_ru.html` / `_thai.html`: вставляешь JSON, полученный от
ИИ, получаешь построчный список несоответствий схеме на понятном языке — до того,
как создавать PR. Работает полностью в браузере, без бэкенда:
`json-validator.js` — самостоятельная реализация нужного подмножества JSON Schema
draft-07 (без сторонних библиотек, доступна и в браузере, и в Node), сверена на
эталонной библиотеке `jsonschema` (Python) без единого расхождения на выборке
живых и специально сломанных JSON. Язык карточки (`ru`/`thai`) определяется
автоматически по наличию `term_ru` или `term_thai`; схема, соответственно,
подгружается с сайта через `fetch('/schema/term.schema.*.json')`.

Страница техническая и рассчитана на того, кто уже получил JSON от ИИ — поэтому в
общее бургер-меню сайта она не выведена, ссылка на неё — только внутри
`how-to-add-term_*.html`, отдельным шагом между «получили JSON» и «создаём файл».

## Отметки «Изучен» и страница «Мой прогресс»

Читатель может отмечать термины изученными. Всё работает на клиенте — без бэкенда и аккаунтов.

- **Хранилище.** Ключ `pali-terms-learned` в `localStorage`, значение — JSON-массив id терминов (например, `["dukkha","sacca"]`). Один статус на id для обоих языков: отметка на русской карточке видна и на тайской. Если `localStorage` недоступен, отметки держатся в памяти до закрытия вкладки.
- **`js/learned.js`** — общий модуль, глобальный объект `window.Learned`: `isLearned(id)`, `set(id, on)`, `toggle(id)`, `all()`, `merge(ids)` (возвращает число добавленных), `clear()`, `refresh(root)`. Клик по любой `.learned-btn[data-learned-id]` обрабатывается одним делегированным обработчиком, поэтому кнопки работают и в динамически созданном HTML. Изменения из другой вкладки подхватываются событием `storage`.
- **Где появляются кнопки.** На плитках навигатора их пишет `build-terms.js` (шаг 5 сборки). На карточке термина — блок `<div id="learned-bar">` в `_template_*.html`, который `learned.js` наполняет кнопкой и пояснением (id термина берётся из имени файла). На заглушках «перевод отсутствует» сборка этот блок убирает (изучать там нечего); в `index_<lang>.json` и навигатор заглушки не попадают. Общая строка-пояснение над списком навигатора — `<p id="learned-nav-note">` в `_template_nav_*.html`, наполняется тем же скриптом.
- **Блёклость.** У плитки изученного термина класс `is-learned` (`.term-item.is-learned > a { opacity: .5 }`), в подсказках поиска тот же класс ставит `search.js` на ссылку. Стили — в `css/learned.css`; цвета «изучено» и «ошибка» заданы переменными для тёмной и светлой темы.
- **Страница «Мой прогресс»** (`/progress_ru.html`, `/progress_thai.html`; статичные, `noindex`; логика — `js/progress.js`):
  - счётчик «Изучено X из Y» и полоска: Y — число терминов в `index_<lang>.json`, X — отметки, для которых термин есть в этом манифесте;
  - **скачать** — файл `pali-terms-progress-ГГГГ-ММ-ДД.json` вида `{"format": "pali-terms-progress", "version": 1, "exported": "<ISO-дата>", "learned": ["<id>", …]}`; пустой список не выгружается;
  - **загрузить** — файл проверяется (`format` совпадает, `learned` — массив, размер до 1 МБ, не более 5000 id, каждый id по маске `[A-Za-z0-9_-]{1,100}`), затем отметки **объединяются** с текущими, ничего не стирается; чужой или битый файл отклоняется без изменений;
  - **сбросить** — `Learned.clear()` после подтверждения на месте кнопки (без отметок кнопка неактивна, Esc отменяет). При смене формата файла увеличивать `version` и учитывать это в `parseProgressFile` в `progress.js`.
  - **список изученных** — термины по алфавиту (имена из `index_<lang>.json`, порядок по правилам языка страницы), по 10 на странице, листание без перезагрузки. Кнопка «Изучен» у строки снимает отметку: на месте строки появляется сообщение со ссылкой «Вернуть», а термин переходит в список не изученных;
  - **список не изученных** — все остальные термины языка страницы (разница между `index_<lang>.json` и отметками), тот же порядок и пагинация, своя страница листания. Кнопка «Не изучен» ставит отметку: на месте строки сообщение со ссылкой «Вернуть», термин переходит в список изученных. Когда не изученных нет, показывается «Все термины изучены.»;
  - **сообщения рядом с элементом.** Сообщения показываются там, где пользователь действует, а не в общей строке внизу: в списках — строка-сообщение на месте нажатой строки (одна на всю страницу, пропадает при следующем действии), у скачивания, загрузки и сброса — строка статуса под кнопкой (`#progress-status-export`, `-import`, `-reset`), ошибка запуска — под счётчиком (`#progress-status-top`). После «Вернуть» список переходит на страницу, где термин вернулся, и фокус ставится на его кнопку. Это правило для всех новых интерфейсов проекта.
- **Меню и ссылки.** Пункт «Мой прогресс» — в `burger-menu.js`; ссылки на страницу — в пояснении на навигаторе и на карточке термина.
- **Новый язык.** Строки интерфейса живут в объектах `STR` внутри `learned.js`, `progress.js` и `burger-menu.js`; для нового языка добавить их во все три файла, добавить код языка в `LANG_BY_HTML_LANG` в `lang.js` и создать `progress_<lang>.html`.

## Связанные термины

Тематические «вязанки» уже добавленных терминов (например, четыре качества Дхаммы),
которые полезно изучать вместе. Это потомок обычных терминов: без терминов связок нет,
но сборка связок никогда не блокирует сборку и публикацию терминов. В интерфейсе слово
«бандл» не используется, только «связанные термины» (тайский: «ชุดศัพท์ที่เกี่ยวข้อง»).

**Как добавить связку.** Положить файл `_src/bundle/json/bundle_<N>_<ru|thai>.json`
и отправить в GitHub (через Pull request, как обычный термин). `N` — любое целое число
без ведущих нулей: уникальное, пропуски допустимы, после публикации не меняется и не
переиспользуется (оно входит в URL). Формат — ровно три ключа:

```json
{
  "name": "Четыре качества Дхаммы",
  "description": "Почему эти термины изучаются вместе.",
  "terms": ["sanditthiko", "akalika", "opanayiko", "ehipassiko"]
}
```

`terms` — id существующих терминов; порядок массива — порядок на странице. Язык и
номер берутся только из имени файла. Состав и порядок `terms` в `_ru` и `_thai` версиях
одной связки обязаны совпадать. Один термин может входить в несколько связок.

**Страницы** (все в `bundle/`, `noindex`, с хлебными крошками):
- `bundle/index.html` (адрес `/bundle/`, русская первая страница), `bundles_ru_2.html`…, `bundles_thai.html`, `bundles_thai_2.html`… — список связок (`bundle/bundles_ru.html` — заглушка → `/bundle/`): плитка с названием,
  описанием, числом терминов и перечнем (до 5, дальше «и ещё N»), пагинация 10 на странице.
  Порядок: новые сверху, то есть по убыванию номера в имени файла (больший номер — выше);
  зазор между плитками такой же, как в навигаторе терминов (общий `.term-list`).
  Если связок нет — текст «Связанные термины пока не добавлены». Пункт меню ведёт сюда.
- `bundle/bundle_<N>_<язык>.html`, `…_2.html` — страница связки, устроена как навигатор терминов
  (плитки, «Изучен», поиск по всем терминам).
- Если есть файл связки только на одном языке, на втором создаётся заглушка с инструкцией
  по переводу (в списке её нет).

**Ошибки.** Связка с ошибкой не публикуется ни на каком языке, где она неверна;
остальные собираются как обычно, а workflow в конце помечается красным и пишет
в лог (и аннотацией) файл, номер и причину. Коды:

| № | Ошибка |
|---|--------|
| 1 | имя файла не `bundle_<число>_<ru\|thai>.json` |
| 2 | невалидный JSON или корень не объект |
| 3 | нет ключа `name`, `description` или `terms` |
| 4 | лишний ключ |
| 5 | `name`/`description` не строка или пустая |
| 6 | `terms` не массив непустых строк |
| 7 | в `terms` меньше 2 терминов |
| 8 | повтор id внутри связки |
| 9 | id не существует в системе |
| 10 | термин не переведён на язык связки |
| 11 | состав или порядок `terms` в `_ru` и `_thai` различаются — не публикуются обе версии |
| 12 | текст не на языке файла (в `_ru` нет кириллицы, в `_thai` нет тайских символов) |

Если ошибка в одной языковой версии (кроме №11), вторая версия публикуется, а для
ошибочной ни страницы, ни заглушки не создаётся.

**Сборка.** `build-bundles.yml` запускается: при push в `_src/bundle/**`,
`build-bundles.js` и `site-config.js`; после каждой успешной сборки терминов
(`workflow_run`: связки перепроверяются, если термин удалён или потерял перевод);
вручную. Сначала прогоняются автотесты `test-bundles.js`, затем `build-bundles.js`
целиком пересобирает `bundle/` (устаревшие страницы исчезают), бот коммитит
результат с `[skip ci]`. Скрипт только читает термины и пишет только в `bundle/`.
Для общих скриптов (`search.js`, `learned.js`, `burger-menu.js`, `term-count.js`)
пути строятся через `TermsLang.url('…')` из `lang.js` от корня сайта, поэтому
они работают на страницах любой глубины.

**Ограничения.** Размер страницы (10) продублирован константой в `build-bundles.js`
и `build-terms.js`; `build-bundles.js` использует `render-term.js` и `thai-numerals.js`.

## Публикации

Статьи для читателей: плитки на страницах-списках и отдельные страницы статей. Это
отдельная функциональность, независимая от терминов и связок: сборка публикаций не
блокирует их сборку и не блокируется ими. Публикация пишется на одном языке и не
переводится (русские статьи для русских читателей, тайские для тайских), поэтому
страницы-заглушки перевода не создаются. Пункт меню «Публикации» (тайский: «บทความ»)
стоит под «Мой прогресс».

**Как добавить публикацию.** Три файла и push в `main`:
1. Текст статьи: `_src/publications/html/<имя>.html` — HTML-фрагмент (см. ниже).
2. Обложка: `publications/covers/<файл>` (jpg, jpeg или png).
3. Плитка: `_src/publications/json/publication_<N>_<ru|thai>.json`.

`N` — любое целое число без ведущих нулей: уникальное в пределах языка, пропуски
допустимы, после публикации не меняется и не переиспользуется. Язык берётся только из
имени файла. Чем больше `N`, тем новее публикация: плитка с наибольшим номером стоит
первой. Даты в JSON нет. Формат — ровно четыре ключа:

```json
{
  "cover": "publications_1.jpeg",
  "headline": "Заголовок статьи",
  "lead": "Лид: два-три предложения.",
  "html": "plavnoe-pogruzhenie-v-buddizm.html"
}
```

`cover` — имя файла из `publications/covers/`, `html` — имя файла из `_src/publications/html/` (только имя, без папок).
Имя статьи: строчные латинские буквы, цифры и дефис, оканчивается на `.html`;
уникально среди всех языков. Из-за подчёркивания имена `publications_ru…` и
`publications_thai…` (страницы списков) заняты автоматически; имя `index.html` зарезервировано (ошибка 15).

**Страницы** (все в `publications/`, пишет только сборка):
- `publications/index.html` (адрес `/publications/`, русская первая страница), `publications_ru_2.html`…, `publications_thai.html`… — список (`publications/publications_ru.html` — заглушка → `/publications/`): плитка с обложкой,
  заголовком, лидом (до 4 строк) и призывом «Читать далее» (тайский: «อ่านต่อ»), 10 плиток на странице, пагинация. Порядок: новая
  сверху. Нет публикаций на языке — страница есть, с текстом «Публикации пока не
  добавлены» и `noindex`.
- `<имя>.html` — статья: хлебные крошки, обложка, единственный `<h1>` (из `headline`),
  лид, оглавление (если в статье 3 и больше `<h2>`), якоря `s1`, `s2`… у
  заголовков, затем тело статьи.
- Шапка, меню, переключатели языка и темы, поиск терминов и подвал — как на остальных
  страницах. Каркасы: `_src/publications/template/_layout_ru.html`, `_layout_thai.html`.
  Переключатель языка на любой странице публикаций ведёт на
  первую страницу списка другого языка (`/publications/` или `/publications/publications_thai.html`).

**Статья: HTML-фрагмент.** Файл в `_src/publications/html/` — только тело статьи, без `<html>`, `<head>`,
`<body>` и `<h1>`. Сборка оборачивает его в каркас и пишет готовую страницу в `publications/`.
Разрешены только перечисленные элементы:
- `h2`, `h3`, `p`, `ul`, `ol`, `li`, `strong`, `em`, `br`, `sup`, `sub`, `code`, `small`, `hr`;
- `a`: `href` (относительный или `https://`; внешние ссылки открываются в новой вкладке с
  `rel="noopener noreferrer"`) или `data-term="<id>"` — ссылка на термин, сборка
  подставляет адрес карточки на языке статьи;
- `blockquote` (с `cite`); `figure` (с `figcaption`) и `img` (`src` — только имя файла из
  `covers/`, `alt` обязателен); `details` с `summary`; `table` (`thead`, `tbody`, `tr`,
  `th`, `td`, у ячеек `colspan`/`rowspan`) — сборка оборачивает таблицу в контейнер с
  горизонтальной прокруткой;
- `aside` только с классами `callout`, `callout--key`, `callout--practice`,
  `callout--important` — сборка сама добавляет заголовок выноски («Ключевая мысль»,
  «Практика», «Важно»).

Запрещено: `script`, `style`, `iframe`, `h1`, `html`, `head`, `body`, атрибуты `style`,
`id`, обработчики `on*`, любые другие `class`, внешние картинки, ссылки не на `https://`.
Все теги закрываются явно. Сборка отклоняет и следы ИИ-ассистентов в тексте
(`[cite: …]`, `oaicite`, `contentReference`, `【…】`).

**Обложки и картинки.** Обложка одновременно плитка, шапка статьи и `og:image`
(превью ссылки в мессенджерах). Рекомендуется 1200×630, показывается с обрезкой по
краям. Картинки внутри статьи лежат в той же папке `covers/`.

**Ошибки.** Публикация с ошибкой не создаётся (ни плитка, ни страница), остальные
собираются как обычно; workflow в конце помечается красным и пишет файл и причину.

| № | Ошибка |
|---|--------|
| 1 | имя JSON не `publication_<число>_<ru\|thai>.json` |
| 2 | невалидный JSON или корень не объект |
| 3 | нет ключа или лишний ключ (ровно `cover`, `headline`, `lead`, `html`) |
| 4 | значение не строка или пустое |
| 5 | в `cover`/`html` путь с папками или недопустимое имя |
| 6 | нет файла обложки в `publications/covers/` |
| 7 | нет файла статьи в `_src/publications/html/` |
| 8 | обложка: не jpg/jpeg/png, не картинка (проверка по сигнатуре) или больше 1 МБ |
| 9 | `headline`/`lead` не на языке файла (нет кириллицы в `_ru`, тайских символов в `_thai`) |
| 10 | одна статья указана в нескольких JSON |
| 11 | в статье недопустимый тег или атрибут, незакрытый тег, `<img>` без `alt`, мусор ИИ |
| 12 | статья пустая |
| 15 | имя статьи зарезервировано: `index.html` или начинается с `publications_` |

Два случая не снимают статью с сайта, но дают красный статус: ссылка `data-term` на
несуществующий или не переведённый на язык статьи термин (код 13: ссылка становится
обычным текстом) и рисунок без файла или не картинка (код 14: рисунок пропускается).
Так удаление термина не убивает уже опубликованную статью.

Предупреждения в логе (публикация создаётся): `headline` длиннее 120 или `lead`
длиннее 400 символов; текст статьи короче 300 символов; обложка уже 1200 px или
пропорция заметно не 1,91:1; файл в `_src/publications/html/` без JSON (не публикуется).

**Сборка.** `build-publications.yml` запускается: при push в `_src/publications/**`, `publications/covers/**`, `css/publications.css`
и в скрипты `build-publications.js`, `test-publications.js` и `site-config.js`; после каждой успешной
сборки терминов (`workflow_run`: ссылки на термины перепроверяются); вручную. Сначала
автотесты, затем `build-publications.js` целиком пересобирает `publications/*.html`
(устаревшие страницы исчезают, `covers/` не трогается), бот коммитит их и `sitemap_publications.xml` с
`[skip ci]`. Скрипт только читает термины и пишет только в эти два места. HTML-фрагмент
проверяется собственным небольшим сканером тегов без зависимостей.

**SEO.** У статьи: `canonical`, `meta description` из `lead`, Open Graph с обложкой, без
`hreflang` (перевода нет). У списка: `canonical`, `prev`/`next`, описание; список без
публикаций — `noindex`. Адреса списков и статей собирает в отдельный файл
`sitemap_publications.xml` (корень сайта) только `build-publications.js`, поэтому
`sitemap.xml` и сборка терминов не затронуты. Файл подаётся поисковикам отдельно, через
их кабинеты.

**Новый компонент статьи.** Три действия: стиль в `publications.css`, строка в белом
списке (`ALLOWED`) в `build-publications.js`, описание в промте для ИИ. Уже
опубликованные статьи не меняются.

**Ограничения.** Размер страницы (10) продублирован константой в `build-publications.js`,
`build-bundles.js` и `build-terms.js`; `build-publications.js` использует `render-term.js`
и `thai-numerals.js`. Сканер тегов не заменяет полный HTML-парсер: поэтому явные
закрывающие теги обязательны. Даты публикации нет, порядок задаёт только номер в имени JSON.

## SEO и индексация

- Каждая карточка и страница навигатора несёт `canonical`, `hreflang` (там, где есть
  обе языковые версии) и Open Graph-теги — see «Архитектура сборки» выше.
- `sitemap.xml` собирается автоматически (шаг 7 сборки) и подан в Google Search
  Console, Bing Webmaster Tools и Яндекс.Вебмастер.
- Страницы `progress_*.html` личные: `noindex`, в `sitemap.xml` не входят.
- Страницы связанных терминов (`bundle/*`, кроме заглушки `bundles_ru.html`) — `noindex`, без
  `canonical` и `hreflang`, в `sitemap.xml` не входят (его строит только `build-terms.js`).
- Страницы публикаций (`publications/*.html`) индексируются (список без публикаций — `noindex`);
  их адреса лежат в отдельном `sitemap_publications.xml`, который строит только
  `build-publications.js` — подробнее в разделе «Публикации».
- Картинки для превью ссылок (`og:image`) у карточек терминов и навигатора пока нет: Open Graph
  настроен, но без неё превью в мессенджерах остаётся текстовым. У публикаций `og:image` — их обложка.
- `robots.txt` лежит в корне сайта: `Allow: /` и две строки `Sitemap:` (`sitemap.xml`, `sitemap_publications.xml`).
- Каждая индексируемая страница имеет ровно один `canonical`, равный её собственному адресу; заглушки на прежних адресах содержат `canonical` на новый адрес и мгновенный `meta refresh`, без `noindex`. Проверяют `test-seo.js` и `test-links.js`.

## Развёртывание у себя (fork)

1. Fork репозитория `indapanno/indapanno.github.io`. Для адреса вида `https://<username>.github.io/` назовите копию `<username>.github.io`.
2. Settings → Pages → Source: `Deploy from a branch`, Branch: `main`, `/ (root)`.
3. Settings → Actions → General → Workflow permissions: `Read and write permissions` (нужно `build-terms.yml` для автокоммита).
4. В `.github/scripts/build-terms.js` поменять константу `SITE_URL` в `.github/scripts/site-config.js` на свой адрес — от неё зависят `canonical`, `hreflang`, Open Graph и `sitemap.xml`.
5. Сайт будет доступен на `https://<username>.github.io/`.
6. Локальная разработка: `node .github/scripts/build-terms.js` из корня репозитория — пересоберёт HTML и `sitemap.xml` без пуша, для проверки перед коммитом.

## Известные ограничения

- Промты для ИИ-генерации (`term-prompt-ru.js`/`-thai.js`) и JSON Schema снижают, но
  не исключают ошибки: схема ловит структуру и типы, а не факты — разные ИИ
  по-разному интерпретируют инструкции, возможны фактические неточности и неверная
  атрибуция источников. Обязательна проверка человеком перед merge.
- Единственный барьер перед кривым JSON сейчас — валидатор, который читатель может
  пропустить (ссылка не обязательна к переходу); автоматической проверки на стороне
  PR ещё нет (см. «Направления развития»).
- Отметки «Изучен» живут только в браузере читателя. Автоматической синхронизации между устройствами нет: перенос вручную, через файл на странице «Мой прогресс». Если браузер очищен, а файл не скачан, отметки потеряны.

## Направления развития

1. **Кросс-ссылки между терминами.** При сборке автоматически превращать упоминания id уже существующих терминов (в `later_mentions[].source.title`, `term_composition`, тексте полей) в `<a href="<id>_ru.html">` — растущий словарь становится связным графом понятий без ручной разметки.
2. **GitHub Action на pull_request** — та же проверка по JSON Schema, что делает `json-validator.js` в браузере, но автоматически на стороне PR: комментарий с ошибками автору, опционально авто-merge при отсутствии ошибок. Схема и валидатор для этого уже готовы, дело за самим Action.
3. **Санитарная проверка ссылок на источники** — эвристическая проверка формата `sources[].location` (диапазоны номеров никай и т.п.), ловит явные несоответствия без претензии на фактчекинг.
4. **Тесты для `build-terms.js`** — smoke-тесты на встроенном `node:test` (Node 18+, без зависимостей): генерация карточки не падает на валидном JSON, капитализация работает, `renderComposition` пуст при `is_compound: false`.
5. **`og:image`** — картинка 1200×630 для превью ссылок в мессенджерах и соцсетях; Open Graph-разметка под неё уже готова. Для публикаций это сделано: превью берётся из обложки.
